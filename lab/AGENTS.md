# AGENTS.md — LAB에 스케치를 추가하는 AI가 지켜야 할 규약

**Claude · GPT 등 어떤 모델이든, LAB 작업을 시작하기 전에 이 파일을 먼저 읽으세요.**
사람(저장소 주인)이 여러 모델에게 번갈아 작업을 시키기 때문에, 이 규약이 유일한 공통 기준입니다.

---

## 0. 가장 중요한 것 — 충돌 방지

이 저장소에서 **여러 에이전트가 동시에 건드릴 수 있는 파일은 단 하나**, `lab/sketches.js` 입니다.
구조를 그렇게 만들어 뒀습니다. 그래서 규칙도 짧습니다.

1. **작업 직전에 `git pull`.** 예외 없습니다.
2. **`lab/sketches.js` 는 맨 아래에 한 줄만 추가.** 중간에 끼워넣거나 기존 줄을 정리하지 마세요.
3. **끝나면 즉시 `git push`.** 로컬에 커밋을 쌓아두지 마세요.
4. **아래 "건드리지 말 것" 목록의 파일은 수정 금지.** 고쳐야 할 이유가 생기면 사람에게 먼저 물어보세요.

`sketches.js` 에서 충돌이 나더라도 해결은 **항상 "두 변경 사항 모두 수락"** 입니다.
두 줄 다 살리면 그게 정답입니다. 다른 해결책을 시도하지 마세요.

### 건드리지 말 것

```
lab/index.html          목록 페이지 — 카드는 자동 생성됩니다
lab/view.html           공용 뷰어
assets/js/lab-core.js   목록·뷰어 공통 로직
assets/js/lab-embed.js  iframe 실행기
assets/js/main.js       필터 · 스크롤
assets/js/zoom.js       이미지 확대
assets/css/style.css    전역 스타일 (스케치 안에서만 쓰는 CSS는 스케치 파일 내부에)
index.html              메인 페이지
```

## 1. 스케치 하나를 추가할 때 만드는 것

**새로 만드는 파일 3~4개 + 기존 파일 1개에 한 줄.** 이게 전부입니다.

| 파일 | 필수 | 내용 |
|---|---|---|
| `lab/sketches/<slug>.html` | 필수 | 스케치 본체. 단일 HTML 한 장 |
| `assets/img/lab/<slug>-card.png` | 필수 | 목록 카드 이미지 **1200×750** |
| `assets/img/lab/<slug>-cover.png` | 필수 | 실행 전 커버 **1600×900** |
| `lab/sketches/making/<slug>.md` | AI 제작이면 필수 | 제작 기록 (아래 3번) |
| `lab/sketches.js` | 필수 | **맨 아래에 `LAB_ADD({...})` 한 줄** |

`slug` 는 영문 소문자·숫자·하이픈만. 위 파일들의 이름이 전부 여기서 파생되므로 반드시 통일하세요.

포스터 이미지는 스케치를 실제로 실행한 뒤 **가장 잘 나온 순간을 캡처**해서 만듭니다.
브라우저를 띄울 수 있다면 직접 캡처하고, 불가능하면 사람에게 요청하세요.
이미지가 없으면 카드가 회색으로 비어 보입니다 (깨지지는 않습니다).

## 2. 스케치 파일 요구사항

### 구조

- **단일 HTML 한 장.** CSS·JS를 파일 안에 넣습니다. 사이트의 `style.css` 를 불러오지 마세요 — 스케치는 iframe 안에서 독립 실행됩니다
- 외부 라이브러리는 **CDN에서 버전을 고정해서** 불러옵니다
  - p5: `https://cdn.jsdelivr.net/npm/p5@1.9.0/lib/p5.min.js`
  - three: `https://cdn.jsdelivr.net/npm/three@0.128.0/build/three.min.js` (전역 `THREE` 를 주는 UMD 빌드)
  - `latest` 같은 태그를 쓰지 마세요. 어느 날 갑자기 깨집니다
- 라이브러리 로드 실패 시 **빈 화면 대신 안내 문구**가 뜨도록 하세요 (`typeof p5 === 'undefined'` 체크)

### 필수 체크리스트

이걸 안 지키면 리뷰에서 되돌아옵니다.

- [ ] `devicePixelRatio` 를 **2로 상한** — 안 두면 고해상도 화면에서 4배 픽셀을 그립니다
- [ ] 탭이 백그라운드로 가면 **루프 정지** (`visibilitychange`)
- [ ] `prefers-reduced-motion: reduce` 면 **움직임 없이 정지 화면**
- [ ] 창 크기 변경(`resize`) 대응
- [ ] 캔버스에 `touch-action: none` — 모바일 스크롤과 안 싸우게
- [ ] 콘솔 에러 0개
- [ ] 일반 노트북(1280×800)에서 **최소 30fps**, 목표 60fps

### 톤

사이트와 같은 언어를 쓰세요. 스케치가 따로 노는 것보다 시스템의 일부로 보이는 게 낫습니다.

```
포인트 컬러  #2D45FF
배경        #FFFFFF
잉크        #111111
쉬는 회색    #C9C9C6 / #8A8A8A
라틴 폰트    Archivo (없으면 Helvetica Neue, Arial)
```

화면 구석에 조작 안내를 한 줄 넣으세요. 11px, letter-spacing 1.2px, 회색.
예: `MOVE TO DISTURB · CLICK TO PULSE`

## 3. 제작 기록 (`by: "ai"` 또는 `"pair"` 일 때 필수)

이 포트폴리오의 주인은 **AI로 만든 작업물을 숨기지 않고, 어떻게 만들었는지를 오히려 보여주는 쪽**을 택했습니다.
그러니 기록은 홍보문이 아니라 **사실 기록**이어야 합니다.

`lab/sketches/making/<slug>.md` 에 아래 형식으로 씁니다.

```markdown
# <제목>

**<모델명> · <연·월> · 대화 N회, 수정 N회**
한 줄 요약.

---

## 시작 프롬프트

> 사람이 실제로 입력한 프롬프트를 **원문 그대로**. 오타도 고치지 마세요.

## AI가 스스로 정한 것

- 지시에 없었는데 모델이 판단한 것들을 구체적으로

## 내가 판단한 것

- 사람이 지시했거나, 되돌렸거나, 거부한 것

## 검증

- 실제로 측정한 수치 (fps, 콘솔 에러 등)

## 남은 한계

- 솔직하게

---

*이 기록은 실제 대화에서 그대로 옮긴 것입니다. 각색하지 않았습니다.*
```

**지켜야 할 선**

- 프롬프트는 **원문 그대로**. 다듬거나 멋있게 고쳐 쓰지 마세요. 그 순간 기록이 아니라 창작이 됩니다
- 대화가 길면 **방향을 결정지은 프롬프트 3~5개**만 발췌하고 나머지는 요약합니다
- 측정하지 않은 수치를 쓰지 마세요. fps를 안 재봤으면 그 줄을 빼세요
- "AI가 만들었지만 사람이 다 통제했다" 식으로 포장하지 마세요. 지시가 한 줄이었으면 한 줄이었다고 쓰는 게 맞습니다

## 4. `sketches.js` 에 추가하는 한 줄

```js
LAB_ADD({
  slug: "flow-field",
  title: "Flow Field",
  tech: "p5.js",
  year: "2026",
  by: "ai",                    // "human" | "ai" | "pair"
  model: "GPT-5",              // by 가 ai/pair 일 때 필수
  summary: "한두 문장.",
  making: true                 // making/<slug>.md 를 썼으면 true
});
```

`by: "ai"` 또는 `"pair"` 면 목록 카드에 **AI-MADE 배지**가 자동으로 붙습니다.
`by: "human"` 이면 배지가 없습니다. 이 값을 사실과 다르게 적지 마세요.

## 6. 작업을 끝내기 전 확인

- [ ] 브라우저에서 `lab/index.html` 을 열어 카드가 뜨는가
- [ ] 카드를 눌러 `view.html?s=<slug>` 가 열리고 스케치가 실행되는가
- [ ] 제작 기록이 뷰어 아래에 렌더되는가 (`making: true` 인 경우)

- [ ] 콘솔 에러 0개

`.pde` 파일은 `http(s)` 로 올린 뒤에만 동작합니다. 로컬에서 확인하려면
저장소 폴더에서 `python -m http.server` 를 띄우고 `localhost:8000` 으로 여세요.
