# Laputa

**GPT-6 Astra Light · 2026·09 · 대화 6회, 수정 2회**
사용자가 제공한 라퓨타 모델을 웹용으로 최적화하고, 회전·확대·지점 탐색을 연결했습니다.
모델명은 이 작업 대화에서 사용자가 지정한 표기를 유지했습니다. 대화 횟수는 라퓨타 기획부터 구현 요청까지의 사용자 메시지 기준이며 수정 횟수는 구현 후 수정 요청 기준입니다.

## 시작 프롬프트

> 현재 웹 디자인이 조금 바뀌었다. 너는 웹 디자인은 절때 건들지말고 그냥 규약에 따라 웹 인터랙션을 계속 만들어볼거야. 내가 라퓨타 블렌더 파일이 있는데, 이 파일 업로드 해줄테니 너가 한번 보고 웹 상에 올릴 수 있을 지 한번 봐바.

> 오케이 그럼 웹용 최적화 및 필요한 사항들 다 진행해서 한번 웹용 만들어봐.

앞선 기획에서는 사용자가 웅장하고 섬세한 라퓨타를 탐색하는 경험과 마우스 회전·휠 확대를 원했습니다. 캐릭터를 클릭하면 인사하는 장기 구상도 있었지만 제공 모델에는 캐릭터 뼈대와 애니메이션이 없었습니다.

## AI가 스스로 정한 것

- 원본 GLB는 수정하지 않고 glTF Transform 4.2.1로 별도의 웹용 GLB를 만들었습니다.
- 중복 제거, 정적 메시 병합, 정점 병합, Draco 압축, 최대 2048px WebP 텍스처 변환을 적용했습니다. 폴리곤 단순화는 적용하지 않았습니다.
- 병합 후 투명 재질 정렬 문제를 발견해 BLEND 재질을 alphaCutoff 0.5의 MASK로 변환했습니다. 잎의 반투명 가장자리 표현은 원본과 다릅니다.
- 버전 고정 Three.js 0.128.0과 GLTFLoader, DRACOLoader, OrbitControls를 사용했습니다.
- 더블클릭으로 선택한 표면에 시점을 집중하고, 방향키와 +/- 및 H 키로도 조작하게 했습니다.
- 자동 움직임 없이 입력·크기 변경 시에만 렌더링하여 정지 상태의 GPU 작업을 줄였습니다. 동작 줄이기 설정에서도 자동 움직임이 없습니다.
- 단일 HTML과 별도로 모델 자산 assets/models/lab/laputa-web.glb를 추가했습니다.

## 재질과 모바일 메모리 수정

> 봤는데 이거 이런식으로 매터리얼이 깨져서 나옴. 이거 어떻게 해야함. 그리고 이거 모바일에서는 튕킴. 그리고 자세히보면 라퓨타 성 위쪽에는 흰색 매터리얼의 벽돌 건물인데 그냥 다 하나의 색으로 통일됐음.

- 원본의 메시 구조와 UV를 유지한 기준 모델에서도 벽면의 잘못된 정점 음영을 재현했습니다. 건축 재질의 평면 음영으로 삼각형 모양의 음영 왜곡이 없어지는 것을 비교 확인했습니다. 해당 건축 재질의 노멀맵도 제외했습니다.
- 상단 일부 건물은 제공된 GLB에도 황토색 돌 텍스처로 연결되어 있었습니다. 사용자가 설명한 의도에 따라 *4, *6, Stone_Sandstone_Ashlar_Light 재질을 GLB 안의 흰 벽돌 텍스처에 연결했습니다. Blender 원본의 정확한 재질을 복구한 것이라고 주장하지 않습니다.
- 큰 반복 UV 좌표의 정밀도를 유지하려고 UV는 float32로 보존하고 위치·노멀만 양자화했습니다. Draco 대신 버전 고정 Meshopt 0.24.0 디코더를 사용합니다.
- 데스크톱: 약 30.72MB, 1,380,889 삼각형. 모바일: 약 12.78MB, 738,410 삼각형. 모바일에서는 기하 단순화, 512px 텍스처, 노멀·거칠기·AO 텍스처 제거를 적용했습니다.
- 텍스처 해상도에서 계산한 RGBA8+밉맵 GPU 메모리 추정값은 이전 약 760.6MB에서 모바일 약 24.5MB로 감소했습니다. 이 값은 실제 프로세스 메모리 측정값이 아니며 기하·프레임버퍼·로딩 임시 메모리를 포함하지 않습니다.
- 터치 중심 기기, 초기 폭 800px 이하, 메모리 정보가 4GB 이하인 기기는 모바일 모델 하나만 불러옵니다. 모바일 DPR은 1.25로 제한하고 안티앨리어싱을 끕니다. Skyward 모바일 구름은 26개로 줄였습니다.
- 실제 휴대폰의 종료 원인은 기기에서 직접 재현하지 못했습니다. 위 경량화로 메모리 부담을 낮췄지만 해당 기기에서 재확인이 필요합니다.
- 비교 렌더링과 확대 화면에서 벽면 음영과 흰 건물의 분리를 확인했습니다. 헤드리스 Chrome의 데스크톱 및 모바일 에뮬레이션에서 약 60fps였고 JavaScript·콘솔 오류는 0개였습니다.
